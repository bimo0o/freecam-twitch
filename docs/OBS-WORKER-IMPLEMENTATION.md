# OBS и MSE worker · состояние 0.5.0

Нативный модуль и перехват MSE в dedicated worker реализованы и проверены локально. Это **alpha**; общая совместимость живых Twitch-плееров ещё не подтверждена.

## Нативный OBS

Модуль создаёт приватную копию готовой сцены без камеры, захватывает фон под её координатами, кодирует 640×360 через x264 и внедряет SEI в штатные выходные пакеты OBS. Видимость источников оригинала не переключается. Есть мастер выбора сцены/камеры и панель общего/дополнительного битрейта, отдельно для передачи и записи.

Сборка ограничена OBS 33.0.1, Windows x64 и холстом/выходом 1920×1080 при 30 FPS. Камера — верхний уровень, без поворота и границ. Структурные изменения сцены приостанавливают восстановление до новой подготовки. Подготовка во время записи/эфира запрещена. Автоматического запуска эфира нет.

Основное время учитывает PTS/DTS и начальную перестановку B-кадров. Фон выбирается по совпадающему времени. Очереди ограничены, ожидание — максимум 4 мс. При отсутствии совпадения используется маркер паузы. У зрителя зависимые вспомогательные кадры возвращаются в порядок представления перед декодированием.

Память пакета выделяется через libobs с ABI OBS 33.0.1. Это существенное ограничение переносимости. Нативная часть отдельно GPL-2.0-or-later.

Проверки настоящей записи OBS: **118 декодированных фонов, четыре меняющихся цвета, 0 ошибочных кадров** в синтетическом сравнении; B=0 и B=2. Установленное расширение восстановило фон из одного OBS-файла в обычном MSE и MSE worker. Второго медиазапроса нет; шесть сравниваемых моментов совпали, расхождение PTS — 0 мс. Это не замер живой задержки и качества игровых границ.

Мастер прошёл подключение к настоящему OBS WebSocket с паролем, подготовку, запись, остановку и проверку неизменности исходных трансформаций/видимости. В журнале при завершении остаётся счётчик одной утечки; причина не установлена.

[Установка и ограничения](../native/obs-freecam/README.md). API: [obs_output_add_packet_callback](https://docs.obsproject.com/reference-outputs#c.obs_output_add_packet_callback).

## MSE в dedicated worker

Разбор `SourceBuffer.appendBuffer` внедряется в worker до приложения плеера. `MediaSourceHandle` связывается с конкретным `video.srcObject`. Выбор самого большого видео не используется. Пакеты идут через внутренний канал, сообщения приложения сохраняются. Ранние сообщения ждут загрузки module worker. Для Blob worker сохраняется собственный URL, поэтому немедленный отзыв исходного URL не ломает запуск.

Проверены classic/module и Blob classic/module с немедленным `revokeObjectURL`: **по 96 декодированных кадров в Chromium и Edge**. Проверены передача handle напрямую из worker, сообщения приложения и настоящий установленный MV3-пакет.

Режим **выключен по умолчанию**. Включение: значок Freecam, **Совместимость плеера → MSE в worker**, затем обновить канал. При сбое выключить и обновить канал. Синхронный отказ конструктора использует штатный Worker. Асинхронная ошибка запуска требует перезагрузки после отключения режима.

Ограничения: оборачиваются worker того же origin; CSP и настоящий загрузчик Twitch требуют живой проверки. Передача handle через MessagePort, shared/service workers и прозрачность `worker.location` не заявлены. Рекламные переходы и переподключения в живом эфире не проверены. Сбой второго зрителя остаётся открытым до повторного теста у него.

API: [MediaSource.handle](https://developer.mozilla.org/en-US/docs/Web/API/MediaSource/handle).

## Повторение тестов

- `scripts/test-sei-extension.mjs`: установленное расширение, обычный MSE и четыре worker-варианта. `FREECAM_BROWSER_PATH` выбирает браузер, `FREECAM_REPORT` — файл отчёта.
- `scripts/test-sei-popup.mjs`: окно и диагностика; обмен с расширением имитируется.
- `scripts/audit-native-obs.mjs <запись.mkv>`: извлечение SEI и сравнение синтетического фона настоящего OBS.
- `scripts/test-native-obs-extension.mjs <запись.mkv> [--worker]`: декодирование одного файла OBS установленным расширением.
- `scripts/test-native-setup.mjs`: мастер и изолированный OBS; приватные тестовые данные в `.tools/native-ws-test.json`. Чужой OBS/эфир не используется.

Самотест модуля с переменной окружения разрешён только в изолированной копии `/.tools/obs-sandbox/`. Производственный OBS не должен запускаться с тестовыми флагами.
