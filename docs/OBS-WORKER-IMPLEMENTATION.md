# Следующие реализации: OBS и MSE в worker

Статус: исследование API выполнено; готового плагина и прозрачного подключения к Twitch worker пока нет. Эти функции не входят в сборку 0.4.9.

## OBS

На рабочем компьютере установлен OBS 33.0.1 в `D:/obs-studio`. Доступны нативные компиляторы Clang и GCC. Заголовки SDK в установленном OBS не найдены.

Официальный API `obs_output_add_packet_callback` доступен начиная с OBS 31.0. Он позволяет обработать сжатый пакет перед отправкой. Это подходящий путь внедрения SEI в штатный выход без отдельного RTMP-клиента. При изменении памяти пакета необходимы аллокаторы libobs.

Источник: https://docs.obsproject.com/reference-outputs#c.obs_output_add_packet_callback

Нужно реализовать и проверить:

1. Захват отдельной композиции без камеры, без переключения видимости в исходной сцене.
2. Отслеживание трансформации камеры, групп, обрезки и размеров выходного кадра.
3. Кодирование закрытой области с тем же временем кадра; запрос IDR при смене геометрии и возобновлении.
4. Ограниченная очередь по PTS для внедрения в пакет. При отсутствии точного фона — маркер паузы, а не соседний кадр.
5. Панель реального общего и дополнительного битрейта. Нельзя считать битрейт фона по общему размеру пакетов или по данным другого канала.
6. Проверка остановки, переподключения, смены сцены и выгрузки плагина. Никакой отправки эфира при загрузке плагина.

## MSE в dedicated worker

MediaSource создаётся внутри worker. Его MediaSourceHandle передаётся на страницу и назначается `video.srcObject`. Перехват `SourceBuffer` только в основном окне не видит appendBuffer внутри worker.

Источник: https://developer.mozilla.org/en-US/docs/Web/API/MediaSource/handle

Нужен перехват до первого appendBuffer внутри worker и отдельный канал доставки пакетов расширению. Необходимо связать конкретный handle с конкретным плеером: выбор самого большого video не гарантирует правильного источника.

До включения на Twitch требуется стенд с настоящим worker/MediaSourceHandle, несколькими MediaSource, передачей handle, classic/module worker, остановкой, рестартом, рекламой и отсутствующим SEI. Обёртка не должна менять штатные сообщения worker или оставлять неработающее видео при блокировке CSP.

Прозрачную подмену Worker нельзя объявлять готовой по тесту основного окна или включать без проверки восстановления штатного воспроизведения при ошибке запуска.
