# Фактическая проверка — 5 ноября 2026

## Выполнено

- Установлены зависимости, зафиксирован package-lock.json. `npm audit` при установке: 0 найденных уязвимостей. Это результат проверки реестра в момент установки, не гарантия отсутствия уязвимостей.
- Node 22.23.4, TypeScript 7.0.2, Vite 8.3.6: проверка типов и production build выполнены.
- Unit/integration tests: геометрия в 4 viewport и 2 пропорциях; конфигурационные схемы; sync bounds; подпись/алгоритм/срок/роль/канал JWT; файловое сохранение и изоляция каналов; publisher auth; отключение камеры; CORS; session redirect медиапрокси.
- Нативный MediaMTX 1.21.3 на Windows принял **диагностический FFmpeg testsrc2** (H.264, 1280×720, 30 FPS, без аудио) через настоящий RTMP и выпустил HLS fMP4. Это тестовый видеосигнал, не захват реальной камеры.
- Playwright / установленный Microsoft Edge: реальный HLS прошёл через backend и Vite proxy. Проверены `videoWidth == 1280` и продвижение `currentTime`, а не только наличие video-тега.
- Две независимые browser contexts: изменения первой сессии не меняют вторую. Проверены drag, resize, localStorage, reload, hide/show, границы после перехода к 640 px, повторное получение кадров после отказа медиазапросов без перезагрузки страницы.
- Скриншот проверенного узкого интерфейса: `test-results/freecam-verified.png` (цветные полосы — только диагностический источник).

Обнаруженный сквозным тестом дефект исправлен: MediaMTX создаёт HLS session через 307 и использует `session` в ссылках плейлистов. Прокси теперь следует только перенаправлениям своего медиасервера в пределах канала и передаёт session, не пересылая произвольные credentials/query.

## Не проверено

- Физическая камера, OBS Virtual Camera на этом компьютере, использование аппаратного encoder.
- Параллельное реальное вещание в Twitch и его одобрение/review; действующие Twitch Extension credentials не предоставлены.
- Native sandbox Twitch, реклама, pause/theater/fullscreen, Helper latency в живом эфире, Safari, iOS/Android.
- WHIP/ICE/TURN через интернет, NAT, RTMPS, доверенный TLS/DNS production.
- Docker image build/Compose запуск: Docker CLI установлен, daemon недоступен. Для видеотеста использован нативный MediaMTX. Production файлы подготовлены, успешное production-развёртывание не заявляется.
- Нагрузочные испытания на сотнях/тысячах зрителей, измерение CPU/GPU/памяти при реальном OBS. Автоматический лимит медиатрафика не реализован.
- Точность синхронизации двух живых потоков. Проверены расчёт target/clamping и реальное воспроизведение HLS; соответствие кадров Twitch/камеры требует живого эфира и калибровки.

## Воспроизведение проверок

```powershell
npm test
npm run build
# В отдельных терминалах: backend, Vite, MediaMTX; настройка по README
node scripts/publish-camera.mjs --testsrc
npm exec playwright test
```

E2E использует LOCAL_CHANNEL_ID и LOCAL_ADMIN_SECRET из .env, временно сохраняет диагностическую конфигурацию канала и восстанавливает прежнюю в finally. Запускайте на локальном канале, не на production эфире. Нужен действующий testsrc publisher и браузер Edge; на другой ОС задайте BROWSER_BIN абсолютным путём к Chromium/Chrome. Для захвата настоящей камеры уберите `--testsrc`, но автоматическая проверка разрешения ожидает 1280×720.

Синтетический publisher и все локальные процессы проверки останавливаются после завершения работы. ZIP расширения находится в `artifacts/freecam-extension.zip`; это assets для загрузки в Console, не установка без review.
