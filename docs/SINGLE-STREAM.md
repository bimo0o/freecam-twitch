# Freecam: эксперимент с одним видеопотоком

В одном обычном H.264-кадре передаются две неперекрывающиеся области: игра и камера. Браузерный обработчик рисует их отдельно из **одного HTMLVideoElement** в одном requestVideoFrameCallback с фиксацией общего снимка. Аудио остаётся у оригинального video; второй видеопоток, сервер камеры и индивидуальные серверные композиции не нужны.

Это браузерное расширение Manifest V3 для настольного Chromium, не Twitch Video Overlay Extension. Локальная обработка работает; доступ к кадрам, реклама, интерфейс и правила **живого Twitch требуют отдельной проверки**. Загрузка в Chrome Web Store не выполнена, одобрение Twitch не заявляется.

## Открыть локальный тест

Node.js 22.12+, зависимости `npm ci`, FFmpeg в PATH. Backend, MediaMTX и Twitch-аккаунт для этого теста не нужны.

```powershell
# Движущийся диагностический фон и отдельная область камеры
node scripts/generate-packed-demo.mjs
# Либо ваша картинка вместо камеры, путь остаётся только локально:
node scripts/generate-packed-demo.mjs --image "C:\путь\картинка.jpg"
npm run dev
```

Откройте [packed.html?demo=1](http://127.0.0.1:5173/packed.html?demo=1), нажмите **«Собрать игру и камеру»**. Диагностический файл включает тестовый звуковой тон; по умолчанию звук выключен. Видеофайл имеет один видеотрек и один аудиотрек. Переместите камеру за панель ⠿; измените размер за угол ◢. Кнопка **«Исходная компоновка OBS»** немедленно возвращает полный кадр. Можно открыть свой локальный MP4 через выбор файла; файл никуда не загружается.

Области извлекаются из того же декодированного кадра. Независимой сетевой задержки камеры нет. Это не устраняет исходное несовпадение микрофона/камеры в OBS, задержки вывода браузера и возможные пропуски кадров при высокой нагрузке. Никакая заявленная точность lip-sync на живом эфире пока не измерена.

## Сцена OBS

Создайте новую сцену, не меняя существующую рабочую композицию. Общий холст и выход: **1920×1080**, 30 или 60 FPS.

| Источник | Позиция X,Y | Размер |
|---|---|---|
| Полная игра 16:9 | 0,0 | 1600×900 |
| Камера 16:9 | 1600,900 | 320×180 |
| Маркер PNG | 1504,1016 | 48×48 |

Для каждого источника в OBS: **Transform / Edit Transform**, установите точные координаты и масштаб без обрезки нужного содержимого. Игра и камера не должны пересекаться. Свободную область заполните тёмным фоном. Микрофон включается в обычный аудиотрек OBS.

Создание маркера (исходник рисунка также есть в browser-extension/obs-marker.svg):

```powershell
node scripts/generate-obs-marker.mjs
```

В OBS добавьте **Image** → `artifacts/obs-marker.png`. Маркер должен остаться ровно 48×48 в координатах 1504,1016, без прозрачности, фильтров и цветовых эффектов. Он состоит из четырёх квадратов: зелёный/пурпурный сверху, голубой/белый снизу. Расширение ищет этот рисунок перед обработкой. Это признак выбранной компоновки, не криптографическая защита. При сильном сжатии или низком качестве маркер может не распознаться; тогда останется исходный вид.

Сцена отправляется в **один обычный Twitch-эфир**. Не включайте прежний отдельный publisher камеры: этому варианту он не требуется. Не вставляйте страницу packed.html в основной эфир — она является клиентской проверкой, а не источником камеры.

## Расширение зрителя

1. Откройте страницу расширений своего Chromium-браузера (Chrome, Edge или совместимого).
2. Включите режим разработчика и выберите **Load unpacked / Загрузить распакованное расширение**.
3. Выберите папку `browser-extension` в проекте. В ZIP `artifacts/freecam-single-stream.zip` содержатся те же файлы; архив сначала распакуйте.
4. Откройте сам канал на `twitch.tv`, а не сайт со встроенным Twitch iframe.
5. Нажмите значок Freecam → **«Включить на этой странице»**. Автоматического включения на любых каналах нет.
6. Пока маркер не найден, исходное видео остаётся видимым. При обнаружении игра заполняет область просмотра, камера становится перемещаемой.
7. **«Вернуть оригинальный плеер»** убирает обработку и восстанавливает стили video. После перехода на другой канал обработчик отключается; активируйте его заново при необходимости.

Разрешения: только `activeTab`, `scripting`, `storage`; нет фонового сбора вкладок, сетевых запросов из расширения или доступа ко всем сайтам. Позиция и размер сохраняются отдельно для hostname/канала. Нативные загрузки и звук video не меняются. Кадры обрабатываются только на стороне зрителя и никуда не отправляются.

## Что произойдёт с качеством и нагрузкой

- Игра в 1080p-пакете имеет фактическое разрешение 1600×900; камера — 320×180. Увеличение камеры не добавляет деталей. Зрители без расширения видят исходную компоновку с выделенными областями.
- Twitch-транскодирование уменьшает обе области; координаты пересчитываются пропорционально videoWidth/videoHeight. Очень низкое качество может испортить маркер.
- Нет второй передачи камеры, но общая картинка по-прежнему требует разумного битрейта. Доставка не становится бесплатной сама по себе: её выполняет платформа основного потока.
- В браузере один декодер, полный снимок декодированного кадра и две видимые Canvas2D-поверхности (плюс маленькая проба маркера). Игра ограничена 1600×900 в backing canvas, камера — 320×180. Нужно отдельно измерять FPS/CPU/GPU на слабых устройствах; массовая проверка не выполнена.

## Ограничения и возврат исходного плеера

- При отсутствии маркера показывается исходное видео.
- При `SecurityError` доступа к пикселям или обнаружении mediaKeys обработка прекращается. CORS/DRM/защита браузера не обходятся.
- Проверяются некоторые видимые DOM-признаки рекламы Twitch; при их обнаружении возвращается оригинал. Селекторы могут измениться. Реклама в живом Twitch и все варианты плеера не тестировались: нельзя обещать надёжность этого детектора. Маркер также отсутствует в обычном рекламном кадре, но возможен отдельный рекламный слой/другой video-элемент.
- Отключение оригинальных control-элементов Twitch, извлечение прямых playback URL, перехват токенов или изменение запросов не реализуются.
- Обычные нативные controls внутри HTML video скрываются вместе с его изображением; локальный тест предоставляет отдельные кнопки паузы и звука. Реальные controls Twitch находятся в DOM и должны проверяться отдельно.
- Fullscreen контейнера локального теста поддержан. Fullscreen самого video, Picture-in-Picture, мобильное приложение Twitch, cast и protected playback не обещаются.
- Браузерное расширение меняет отображение видео, что требует отдельной оценки по [Developer Agreement Twitch](https://legal.twitch.com/en/legal/developer-agreement/). Техническая возможность не означает разрешение платформы.

## Проверки

```powershell
npm test
npm run build
node scripts/generate-packed-demo.mjs --unmarked
# При запущенном npm run dev и созданном packed-demo.mp4:
npm exec playwright test tests/packed.spec.ts
```

На локальном H.264/AAC MP4 проверены наличие одного video-элемента, рост числа обработанных кадров, соответствие пикселей камеры исходной области, drag/resize, сохранение при повторном включении, изоляция браузерных сессий, hide/show, границы при изменении viewport, отсутствие маркера и повторное распознавание. Сборка и 9 unit/integration tests проходят. Скриншот: test-results/packed-single-stream.png.

Это доказательство локальной обработки одного потока. Проверка настоящего Twitch-эфира с такой сценой ещё не выполнена.

Основание реализации: [Content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), [requestVideoFrameCallback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback), [Canvas drawImage](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/drawImage).

Проверка синхронизации GIF, готовый стенд OBS и актуальные результаты: [STREAM-TEST.md](STREAM-TEST.md).
