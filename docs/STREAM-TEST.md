# Мастер подготовки OBS

Для рабочего эфира доступно [переносимое приложение Windows](https://github.com/bimo0o/freecam-twitch/releases/download/v0.1.0-streamer-preview/Freecam-Streamer-Windows.zip): распакуйте архив и запустите **Freecam Setup.exe**. Оно открывает локальный мастер в браузере, Node.js не нужен. Исходный вариант запуска: **Freecam Setup.cmd** или `/setup.html` при работающем `npm run dev`. OBS 28+ включает WebSocket Server; его требуется один раз включить в Tools → WebSocket Server Settings. Пароль не отключайте.

После подключения выберите два существующих источника и нажмите **«Подготовить и открыть сцену»**. Мастер создаёт новую сцену, общий холст/выход 1920×1080, четыре цветовых элемента маркера и текст установки в нижней полосе. Существующие источники не перенастраиваются: меняется только их расположение в новой сцене. Общие настройки видео OBS меняются на 1080p. Во время эфира/записи операция запрещена.

Применённые координаты и разрешение проверяются ответами OBS автоматически. При ошибке выполняется попытка вернуть прежнее разрешение и удалить только созданные мастером элементы. Пароль не сохраняется в localStorage или файлах. Автоматический старт трансляции не выполняется.

Автоматизация проверена unit-тестами и браузерным тестом с протокольным сервером OBS. Подключение к реальному OBS на этом компьютере требует его WebSocket-пароля и пока не проверено. Это не заменяет проверку ограничений живого плеера Twitch.

# Проверка на настоящем Twitch-эфире

Цель: проверить доступность кадров **в самом Twitch**, точное совпадение двух визуальных копий одной анимации, поведение интерфейса и возврат исходного видео. Локальное воспроизведение эту проверку не заменяет.

## Подготовка стенда

Нужны Node.js 22.12+, FFmpeg, OBS и свой Twitch-канал. Из корня проекта:

```powershell
npm ci
npm run demo:sync
node scripts/generate-obs-marker.mjs
node scripts/prepare-stream-test.mjs
```

В `artifacts/stream-test/` появятся готовый видеоролик `freecam-sync-test.mp4`, отдельный `sync-camera.gif`, PNG-маркер и инструкция. Ролик уже включает всю нужную компоновку: эталон и область камеры получают одну копию декодированного GIF через split, поэтому должны показывать одинаковые номера FRAME. Белая вспышка и звуковой импульс предусмотрены каждые две секунды. Аудиовывод устройства и кодирование AAC могут добавлять задержку; для оценки аудио/видео нужен отдельный просмотр/запись, численная точность не заявляется.

## OBS: пять минут до теста

1. Создайте **новую сцену «Freecam Test»**. Существующий рабочий эфир не меняйте.
2. В **Settings → Video** установите Base Canvas и Output Resolution `1920×1080`, FPS `30`.
3. Добавьте **Media Source / Источник медиа**. Выберите `artifacts/stream-test/freecam-sync-test.mp4`, включите **Loop / Повтор**.
4. Для источника выберите **Transform → Fit to Screen / Вписать в экран**. Не обрезайте края: камера и маркер находятся в нижней полосе.
5. Отключите микрофон и захват звука рабочего стола, оставьте только аудио тестового Media Source. Перед выходом в эфир проверьте preview.
6. Подключите свой Twitch-аккаунт обычным способом. Это один нормальный эфир: отдельного аккаунта и сервера камеры не требуется.
7. Запустите эфир, когда будете готовы показать диагностическую сцену публично. Стенд не нажимает Start Streaming автоматически.

Это тестовый ролик с синтетическим фоном, а не игра и не физическая камера. Для проверки настоящей камеры после этого используйте [компоновку трёх источников](SINGLE-STREAM.md#сцена-obs): игра, камера, маркер.

## Браузер зрителя

1. В настольном Chrome/Edge откройте страницу управления расширениями.
2. Включите **Developer mode / Режим разработчика**, нажмите **Load unpacked / Загрузить распакованное**, укажите `browser-extension/`.
3. Откройте `https://www.twitch.tv/ИМЯ_ВАШЕГО_КАНАЛА`. Для теста нужен сам Twitch, не iframe в нашем локальном сайте.
4. Дождитесь реального воспроизведения эфира. Для начала выберите Source/1080p.
5. Нажмите значок Freecam → **«Включить на этой странице»**. При распознанном маркере общий кадр преобразуется в игру с подвижной камерой.
6. Сравните FRAME в эталонном окошке и в камере. Их значения должны совпадать; визуально проверить удобнее по записи экрана с последующей покадровой остановкой.

Расширение автоматически распознаёт подготовленную компоновку после открытия страницы и перехода между каналами. Это не Twitch Extension из каталога Twitch и не функция мобильного приложения.

## Чеклист перед выводом «работает на Twitch»

| Проверка | Ожидаемое поведение |
|---|---|
| 30 секунд воспроизведения | Анимация двигается, FRAME эталона и камеры совпадают |
| Drag / resize | Камера перемещается и меняет размер, основная игра не сдвигается |
| Скрыть / показать | Камера возвращается, звук не дублируется |
| Выключить обработку | Полный исходный кадр и обычный плеер восстанавливаются |
| Перезагрузить и включить снова | Положение и размер сохраняются для этого канала |
| Второй профиль браузера | Свои независимые настройки |
| Source → 720p → 480p | Координаты областей масштабируются; при потере маркера остаётся оригинал |
| Пауза / продолжить | Звук и обе области управляются одним исходным video |
| Theater / fullscreen | Нет обрезанных кнопок или потерянной камеры; записать ограничения, если проявятся |
| Реклама | Показывается исходная реклама; расширение не должно её закрывать или заменять |
| Переход на обычный канал | Обработка отключается, чужой поток не обрезается |
| Нагрузка | Сравнить dropped frames, CPU/GPU и плавность с выключенной обработкой |

## Когда остановить проверку

- **Нет маркера**: проверьте разрешение, полный кадр Media Source, качество Source и расположение источников. Отсутствующий маркер не следует игнорировать принудительным включением crop.
- **SecurityError / protected video**: браузер запретил обработку; плеер остаётся исходным. CORS, DRM и другие средства защиты не обходятся.
- **Реклама закрыта слоем, пропали controls, ошибки воспроизведения**: отключите Freecam и зафиксируйте браузер/сценарий. Не называйте этот режим готовым к публикации.
- **FRAME расходятся**: сохраните фрагмент видео с обоими счётчиками и укажите качество потока. Локальные тесты проходят, но это не исключает особенностей другого браузера/рендера.

## Что уже проверено локально

В браузерном тесте сравниваются 16 последовательных выборок бинарных номеров кадров, встроенных в GIF. Две вырезанные области совпали; номера меняются, поэтому тест не проходит на неподвижной картинке. Дополнительно проверены drag/resize, сохранение, независимые сессии, скрытие, смена размеров, потеря маркера и искусственный DOM-признак рекламы. Обработчик также загружен через настоящий Manifest V3 в изолированный контекст тестового Chromium. Для автоматизации fixture получает только тестовый доступ к localhost; публичный manifest имеет доступ только к Twitch, а localhost-разрешение добавляется лишь в тестовую копию.

Полноценная проверка рекламы, интерфейса, производительности и синхронизации звука на **живом Twitch** пока не выполнена. Правила платформы также требуют отдельной оценки перед распространением продукта.
